# 中文快速上手与故障处理

## 一个可直接复用的请求

```
为一个部署在国内云的 Python 订单系统选择异步任务队列。
要求：至少一次投递、失败重试、指标和追踪、商用友好许可证；
请比较 3 个候选项目，标出已核验、推断、待核验内容，并给出两周迁移计划和回滚方案。
```

先列出工作负载、延迟、数据敏感性、运维能力和许可证限制。然后按能力分别检索，保留每个候选项目的仓库链接、访问日期、许可证、测试/CI、近期活动、部署示例和复用决定。

## 国内网络与来源回退

优先执行：

```powershell
python scripts/research_repositories.py "async task queue python" --source auto
```

`auto` 先查询 GitHub；GitHub 发生网络、限流或认证问题时会查询 Gitee。输出中的 `source` 是本次成功来源，`fallback_used` 表示是否使用回退，`failed_sources` 保存失败原因。Gitee 的搜索结果只用于建立候选列表，仍要阅读许可证、源码、测试和官方文档。

若两个来源都不可访问，转为人工检索官方仓库页或 PyPI、npm、Maven Central 等包注册表，并在报告中标记“待核验”。不要因为无法访问 GitHub 就断言项目不存在或质量较差。

## 常见错误

| 现象 | 含义 | 下一步 |
| --- | --- | --- |
| `HTTP 401/403/429` | 认证不足或 API 限流 | 稍后重试；GitHub 可由用户配置 `GITHUB_TOKEN` 提高公开 API 限额；不记录或输出令牌。 |
| DNS、超时、连接重置 | 网络或代理无法访问来源 | 使用 `--source gitee`，或改查官方站点和包注册表。 |
| 返回候选但许可证为空 | 搜索摘要不够 | 打开仓库 LICENSE 文件和依赖清单后再决定是否采用。 |
| 本地盘点结果很多 | 清单只是索引 | 优先阅读 manifest、部署文件、测试和关键入口源文件，不能仅根据文件名推断架构。 |

## 最小输出结构

1. 目标和未决条件。
2. 候选对比表：链接、许可证、维护证据、已核验能力、风险、复用决定。
3. 推荐方案及明确不选原因。
4. 接口/事件、状态、失败恢复、观测和权限边界。
5. 分阶段实施、验收、回滚与待核验项。
